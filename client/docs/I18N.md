# AhaduCenter i18n Implementation Guide

## Overview

The AhaduCenter client now has full internationalization (i18n) support for **English (en)** and **Amharic (am)** using `react-i18next`.

### Technologies

- **i18next**: Core i18n framework
- **react-i18next**: React bindings for i18next  
- **i18next-browser-languagedetector**: Auto-detects user language
- **Redux**: Stores language state for app-wide consistency
- **Noto Sans Ethiopic**: Google Font for proper Amharic rendering

### Supported Languages

| Language | Code | Direction | Status |
|----------|------|-----------|--------|
| English  | `en` | LTR       | ✅ Complete |
| Amharic  | `am` | LTR       | ✅ Complete |

## Architecture

### File Structure

```
src/
├── i18n/
│   ├── config.ts           # i18next initialization
│   ├── types.ts            # TypeScript language types
│   ├── hooks.ts            # useLanguage custom hook
│   └── locales/
│       ├── en.json         # English translations (350+ keys)
│       └── am.json         # Amharic translations (350+ keys)
├── utils/
│   └── i18nFormat.ts       # Date formatting utilities
├── hooks/
│   └── useToast.ts         # i18n-aware toast hook
└── components/
    └── common/
        ├── LanguageSwitcher.tsx  # Toggle EN ⇄ አማ
        └── Toast.tsx             # Translated toast component
```

### How It Works

1. **Detection**: On first visit, i18next checks:
   - `localStorage.getItem('ahadu.lang')` (user's previous choice)
   - `navigator.language` (browser language)
   - Falls back to `'en'` if neither exists

2. **State Management**: 
   - Redux stores `language` in `state.language.language`
   - Synced with i18next via `setLanguage` action

3. **HTML Lang Attribute**: 
   - Automatically updates `<html lang="en|am">` on language change
   - Improves accessibility and SEO

4. **Font Loading**:
   - Noto Sans Ethiopic loaded from Google Fonts CDN
   - Fallback chain: `'Inter', 'Noto Sans Ethiopic', sans-serif`

## Usage

### Basic Translation

```tsx
import { useTranslation } from 'react-i18next';

function MyComponent() {
  const { t } = useTranslation();

  return (
    <div>
      <h1>{t('common.welcome')}</h1>
      <button>{t('common.save')}</button>
    </div>
  );
}
```

### Translation with Interpolation

```tsx
// Translation key in en.json: "welcome": "Welcome, {{name}}!"
const { t } = useTranslation();

<h1>{t('welcome', { name: user.name })}</h1>
// Output: "Welcome, John!"
```

### Pluralization

```tsx
// In en.json:
// "itemCount_one": "{{count}} item",
// "itemCount_other": "{{count}} items"

<span>{t('itemCount', { count: items.length })}</span>
// Output: "1 item" or "5 items"
```

### Using the Language Hook

```tsx
import { useLanguage } from '../../i18n/hooks';

function MyComponent() {
  const { language, setLanguage, toggleLanguage } = useLanguage();

  return (
    <div>
      <p>Current language: {language}</p>
      <button onClick={toggleLanguage}>Switch Language</button>
      <button onClick={() => setLanguage('am')}>አማርኛ</button>
    </div>
  );
}
```

### Date Formatting

```tsx
import { useTranslation } from 'react-i18next';
import { formatShortDate, formatLongDate } from '../../utils/i18nFormat';

function MyComponent() {
  const { i18n } = useTranslation();
  const date = new Date('2024-01-15');

  return (
    <div>
      <p>Short: {formatShortDate(date, i18n.language)}</p>
      {/* English: "Jan 15, 2024" */}
      {/* Amharic: "ጃንዩ 15, 2024" */}
      
      <p>Long: {formatLongDate(date, i18n.language)}</p>
      {/* English: "January 15, 2024" */}
      {/* Amharic: "ጃንዩወሪ 15, 2024" */}
    </div>
  );
}
```

### Toast Messages

```tsx
import { useToast } from '../../hooks/useToast';

function MyComponent() {
  const { toast, showToast } = useToast();

  const handleSave = () => {
    // ... save logic
    showToast('toasts.saveSuccess', {}, 'success');
  };

  return (
    <div>
      <button onClick={handleSave}>Save</button>
      {toast && <Toast message={toast.message} type={toast.type} />}
    </div>
  );
}
```

## Adding Translations to a Component

### Step-by-Step Process

1. **Import useTranslation**:
   ```tsx
   import { useTranslation } from 'react-i18next';
   ```

2. **Get the translation function**:
   ```tsx
   const { t } = useTranslation();
   ```

3. **Replace hardcoded strings**:
   ```tsx
   // Before
   <button>Save</button>
   
   // After
   <button>{t('common.save')}</button>
   ```

4. **Add translation keys to locale files**:
   ```json
   // en.json
   {
     "common": {
       "save": "Save"
     }
   }
   
   // am.json
   {
     "common": {
       "save": "አስቀምጥ"
     }
   }
   ```

### Translation Key Naming Convention

Use hierarchical dot notation:

```
domain.category.key
```

Examples:
- `nav.home` - Navigation item
- `auth.loginTitle` - Auth page title
- `movies.requestMovie` - Movie-specific action
- `common.save` - Shared across app
- `toasts.success` - Toast notification
- `validation.required` - Form validation

## Adding a New Language

To add a third language (e.g., Tigrinya `ti`):

### 1. Update Type Definitions

```typescript
// src/i18n/types.ts
export type Language = 'en' | 'am' | 'ti';  // Add 'ti'

export const SUPPORTED_LANGUAGES: Language[] = ['en', 'am', 'ti'];

export const LANGUAGE_NAMES: Record<Language, string> = {
  en: 'English',
  am: 'አማርኛ',
  ti: 'ትግርኛ'  // Add Tigrinya
};

export const LANGUAGE_CODES: Record<Language, string> = {
  en: 'EN',
  am: 'አማ',
  ti: 'ትግ'  // Add code
};
```

### 2. Create Translation File

```bash
cp src/i18n/locales/am.json src/i18n/locales/ti.json
```

Then translate all values in `ti.json` to Tigrinya.

### 3. Import in i18n Config

```typescript
// src/i18n/config.ts
import ti from './locales/ti.json';

i18n.init({
  resources: {
    en: { translation: en },
    am: { translation: am },
    ti: { translation: ti },  // Add resource
  },
  supportedLngs: ['en', 'am', 'ti'],  // Add to supported
  // ...
});
```

### 4. Update Language Switcher (Optional)

If you want a dropdown instead of toggle, update `LanguageSwitcher.tsx` to show all three options.

That's it! The app now supports three languages with < 10 lines of code changes.

## Translation File Structure

### JSON Organization

```json
{
  "common": {
    "loading": "Loading…",
    "error": "Something went wrong",
    "save": "Save",
    "cancel": "Cancel"
  },
  "nav": {
    "home": "Home",
    "movies": "Movies"
  },
  "auth": {
    "loginTitle": "Welcome Back",
    "email": "Email",
    "password": "Password",
    "errors": {
      "required": "This field is required",
      "invalidEmail": "Please enter a valid email"
    }
  }
}
```

### Key Principles

1. **Namespace by domain**: Group related translations (nav, auth, movies, books, etc.)
2. **Max 2-3 levels deep**: Avoid excessive nesting
3. **Use camelCase**: For consistency with JavaScript conventions
4. **Alphabetize keys**: Within each namespace for easy scanning
5. **Keep interpolation placeholders**: `{{name}}`, `{{count}}`, `{{year}}`

## Best Practices

### ✅ DO

- **Use translation keys for all user-visible text**
  ```tsx
  <button>{t('common.save')}</button>
  ```

- **Use interpolation for dynamic values**
  ```tsx
  {t('welcome', { name: user.name })}
  ```

- **Translate aria-labels and placeholders**
  ```tsx
  <input
    placeholder={t('search.placeholder')}
    aria-label={t('search.label')}
  />
  ```

- **Format dates with locale awareness**
  ```tsx
  {formatShortDate(date, i18n.language)}
  ```

- **Keep translation keys in English**
  ```json
  { "save": "አስቀምጥ" }  // ✅ Key in English, value in Amharic
  ```

### ❌ DON'T

- **Don't concatenate translated strings**
  ```tsx
  // ❌ BAD
  {t('hello') + ' ' + user.name}
  
  // ✅ GOOD
  {t('greeting', { name: user.name })}
  ```

- **Don't hardcode user-facing text**
  ```tsx
  // ❌ BAD
  <button>Save</button>
  
  // ✅ GOOD
  <button>{t('common.save')}</button>
  ```

- **Don't translate API responses directly**
  ```tsx
  // ❌ BAD
  <p>{apiError}</p>
  
  // ✅ GOOD (map error codes to translation keys)
  <p>{t(`errors.${errorCode}`)}</p>
  ```

- **Don't use machine translations without review**
  - The Amharic translations in this project are machine-generated
  - Review and refine them for accuracy and naturalness

## Troubleshooting

### Missing Translation Warning

**Problem**: Console shows `"key 'some.key' not found"`

**Solutions**:
1. Add the key to both `en.json` and `am.json`
2. Check for typos in the key name
3. Ensure JSON structure matches (same nesting level)
4. Restart dev server after adding keys

### Amharic Text Shows Boxes (□□□)

**Problem**: Amharic characters don't render

**Solutions**:
1. Verify Noto Sans Ethiopic is loaded in `index.html`
2. Check font-family in `index.css` includes `'Noto Sans Ethiopic'`
3. Clear browser cache and reload

### Language Doesn't Persist

**Problem**: Language resets on page refresh

**Solutions**:
1. Check localStorage key is `'ahadu.lang'` (matches i18n config)
2. Verify LanguageDetector is configured correctly in `i18n/config.ts`
3. Check browser doesn't block localStorage
4. Ensure `setLanguage` action dispatches correctly

### TypeScript Errors with t()

**Problem**: TypeScript complains about `t()` return type

**Solutions**:
1. Ensure `i18next` types are installed: `npm install --save-dev @types/i18next`
2. Check module augmentation in `i18n/types.ts`
3. Restart TypeScript server in VS Code

## Performance

### Bundle Size Impact

- **i18next core**: ~50KB (gzipped: ~18KB)
- **react-i18next**: ~12KB (gzipped: ~4KB)
- **LanguageDetector**: ~8KB (gzipped: ~3KB)
- **Locale files**: ~30KB combined (gzipped: ~10KB)
- **Total impact**: ~100KB (~35KB gzipped)

This is < 10% of a typical React app bundle.

### Optimization Tips

1. **Lazy load locales** (future):
   ```typescript
   // Load translations on demand
   i18next.loadLanguages(['am']);
   ```

2. **Tree-shake unused features**:
   ```typescript
   // Only import what you need
   import { useTranslation } from 'react-i18next';
   ```

3. **Cache translations**:
   - Translations are cached in memory after first load
   - LocalStorage caches language choice
